## 5. Detailed Verification Findings

### 5.1 Formula Validation

**Total weight = 100%** — verified in `FinancialHealthCalculationEngine`.

### 5.2 Score Validation

- Score range: `0` to `100` with `Math.max(0, Math.min(100, overallScore))`.
- Database constraint `chk_financial_health_scores_overall_score` enforces `BETWEEN 0 AND 100`.
- Labels implemented per v1:
  - `0-39` CRITICAL
  - `40-59` NEEDS_ATTENTION
  - `60-74` FAIR
  - `75-89` GOOD
  - `90-100` EXCELLENT
- Boundary test `scoreCannotExceedHundred` passes.

### 5.3 Factor Validation

- All factor calculations return `int` values.
- `FinancialHealthResult.FactorResult` scores are bounded by per-factor logic and confirmed by `factorScoresInRange` test.
- Overall score is capped to `[0, 100]`.

### 5.4 Data Sufficiency / Confidence

| Historical Months | Confidence | Status |
|-------------------|------------|--------|
| 0 | LOW | PROVISIONAL |
| 1 | LOW | PROVISIONAL |
| 2 | MEDIUM | PROVISIONAL |
| 3+ | HIGH | FINAL |

Verified by `FinancialHealthCalculationEngineTest`:
- `zeroHistoricalMonths_lowConfidence`
- `oneHistoricalMonth_lowConfidence`
- `twoHistoricalMonths_mediumConfidence`
- `threeHistoricalMonths_highConfidence`

Missing data does not produce a poor score; each factor returns a neutral `50` when data is unavailable.

### 5.5 Bill Discipline

- Paid-on-time logic uses due date + 3-day grace period.
- Severe overdue (> 7 days) applies a 5-point penalty.
- No bills scenario returns `100` (neutral).
- Bills are treated as user-recorded statuses only (`PAID`, `PENDING`, `OVERDUE`); no payment execution is performed.

### 5.6 Savings

- Actual/Planned ratio, capping at 100.
- Zero planned savings returns neutral `50`.
- Negative actual savings returns `0`.
- Verified by `negativeSavings_returnsZero` and `noSavingsPlan_returnsNeutralSavings`.

### 5.7 Expense Trend

- Historical average of previous months.
- Piecewise score based on trend percentage.
- Score is capped to `[0, 100]`.
- Missing data returns `50`.
- **Warning:** The optional v1 volatility adjustment (standard deviation > 30% of average) is not implemented.

### 5.8 Emergency Preparedness

- Current / Target × 100, capped at 100.
- Missing target returns `50` (neutral).
- Current = 0 returns `0`.
- No custodial emergency-fund balance is introduced; only user-provided current/target amounts are used.

### 5.9 Savings Goals

- Average of individual goal progress percentages.
- Missing goals returns `50` (neutral).
- Overdue target date applies a monthly penalty.
- **Warning:** The optional v1 time-adjustment (expected progress vs current progress) is not implemented.

### 5.10 Explainability

`FinancialHealthResult` exposes:

- overall score
- label
- confidence
- status
- factor scores, weights, and contributions
- positive contributors
- negative contributors
- recommended actions
- score change with reasons
- algorithm version
- notes

### 5.11 Reproducibility

- `FinancialHealthCalculation` table stores `input_snapshot`, `factor_scores`, `weights`, and `calculation_version`.
- `ALGORITHM_VERSION = "1.1"` is persisted.
- Deterministic engine: same inputs and same version produce the same score.

### 5.12 Security

- `FinancialHealthService.authorize()` verifies user/family membership.
- `FinancialHealthControllerTest.crossFamilyAccessDenied` passes.
- Family A cannot access Family B data.
- Authorization is enforced server-side.

### 5.13 Database

- New migration: `V11__financial_health.sql`.
- V1–V10 were not modified.
- Tables: `financial_health_scores`, `financial_health_factors`, `financial_health_calculations`.
- Correct PK/FK relationships and indexes.
- `weight` and `contribution` use `NUMERIC(5, 2)`.
- No duplicate financial entities.
- No custodial wallet balance or stored-value balance introduced.

### 5.14 Financial Safety

Review of `FinancialHealthCalculationEngine`, `FinancialHealthService`, `FinancialHealthController`, `V11__financial_health.sql`, and the Flutter financial-health screen confirmed the absence of:

- payment execution
- UPI
- BBPS
- bank transfer
- P2P transfer
- wallet transfer
- cash-out
- add money
- withdraw money
- stored-value balance
- custodial funds

### 5.15 API
