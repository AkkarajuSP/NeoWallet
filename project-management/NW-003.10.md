# NW-003.10 — NeoWallet Financial Health Engine

## 1. Scope & Objectives

Implement the NeoWallet Financial Health Engine (NW-003.10) as a deterministic, explainable, versioned, and auditable system. The engine computes an overall financial-health score (0-100) for an individual user or family based on six weighted factors. It explicitly avoids any payment execution or money movement.

**Key goals achieved:**

- Backend persistence and API for financial-health calculations.
- Deterministic `FinancialHealthCalculationEngine` with explainability.
- Authorization, versioning, and audit integration.
- Flutter consumer UI with models, service, provider, and screen.
- Comprehensive backend and Flutter test coverage.
- OpenAPI-aligned DTOs and REST endpoints.

## 3. Backend Implementation

### 3.1 Database Migration

**File:** `neowallet/backend/neowallet-api/src/main/resources/db/migration/V11__financial_health.sql`

Created three tables:

- `financial_health_scores`
- `financial_health_factors`
- `financial_health_calculations`

Indexes and foreign-key constraints are aligned with `NeoWallet_Database_Architecture_v1.md`. JSONB columns store the input snapshot, factor scores, and weights to guarantee reproducibility.

### 3.2 Entities & Repositories

- `FinancialHealthScore`, `FinancialHealthFactor`, `FinancialHealthCalculation`
- `FinancialHealthScoreRepository`, `FinancialHealthFactorRepository`, `FinancialHealthCalculationRepository`
- Added date-bounded `findBillsDueBetween` to `BillRepository`
- Added `findTransactionsForDateRange` to `TransactionRepository`

Entity definitions were aligned with the Flyway schema (e.g., `created_at` timestamps removed where the migration did not define them).

### 3.3 Calculation Engine

**File:** `neowallet/backend/neowallet-api/src/main/java/com/neowallet/finance/engine/FinancialHealthCalculationEngine.java`

Calculates six factors deterministically:

1. **Budget Adherence**
2. **Savings Behavior**
3. **Expense Trend**
4. **Bill Discipline**
5. **Emergency Preparedness**
6. **Savings Goal Progress**

The engine applies the documented weights, score ranges, missing-data neutral scoring, confidence levels, and status labels (`HEALTHY`, `STABLE`, `NEEDS_ATTENTION`, `PROVISIONAL`). It produces:

- `overallScore` (0-100)
- `scoreLabel`
- `confidence` (LOW / MEDIUM / HIGH)
- `status`
- `positiveContributors`, `negativeContributors`
- `recommendedActions`
- `scoreChange`

### 3.4 Service Layer

**File:** `neowallet/backend/neowallet-api/src/main/java/com/neowallet/finance/service/FinancialHealthService.java`

Responsibilities:

- Gathers data from `FinancialOverview`, `Budget`, `Transaction`, `SavingsGoal`, and `Bill` repositories.
- Authorizes user/family access.
- Invokes `FinancialHealthCalculationEngine`.
- Persists score, factors, and calculation snapshot.
- Maps results to DTOs.
- Records `FINANCIAL_HEALTH_CALCULATED` audit events with correct actor type (`USER` / `FAMILY_MEMBER`).
- Throws `ValidationException` for missing income (mapped to `422` by `GlobalExceptionHandler`).

### 3.5 Controller

**File:** `neowallet/backend/neowallet-api/src/main/java/com/neowallet/finance/controller/FinancialHealthController.java`

Exposes OpenAPI-aligned endpoints:

- `GET /api/v1/financial-health`
- `GET /api/v1/financial-health/factors`
- `GET /api/v1/financial-health/history`
- `GET /api/v1/financial-health/explanation`

All endpoints support `X-Family-ID` for family-scoped queries and are protected by JWT.

### 3.6 DTOs

- `FinancialHealthResponse`
- `FinancialHealthFactorsResponse`
- `FinancialHealthHistoryResponse`
- `FinancialHealthExplanationResponse`
- `FactorScoreDto`

## 6. Fixes Applied During Implementation

- Removed `created_at` columns from `FinancialHealthScore` and `FinancialHealthCalculation` entities to match the V11 Flyway schema.
- Added `findBillsDueBetween` to `BillRepository` and used it in `FinancialHealthService` to avoid SQL parameter-type errors.
- Changed missing-income exception to `ValidationException` so `GlobalExceptionHandler` returns `422 Unprocessable Entity`.
- Fixed audit `actor_type` by setting it to `USER` or `FAMILY_MEMBER` based on context.
- Removed `@Transactional(readOnly = true)` from `getFactors` and `getExplanation` because they can lazily persist a missing score.
