# NW-003.11.1 — Neo AI Foundation Final Report

## 1. Executive Summary

NW-003.11.1 establishes the Neo AI Foundation for NeoWallet.

The foundation is a read-only, recommendation-only, deterministic AI layer that sits on top of the approved Financial Health and finance services.

No autonomous financial actions, payment execution, money movement, UPI/BBPS, budget modifications, database direct access, or ADMIN family role were introduced.

## 2. Architecture

```
User
 ↓
Neo Concierge (NeoConciergeService)
 ↓
Intent Classification (IntentClassifier)
 ↓
Policy / Permission Engine (PolicyEngine)
 ↓
AI Orchestrator (AIOrchestrator)
 ↓
Approved Tool Registry (ToolRegistry) — read-only tools
 ↓
NeoWallet Finance Services
 ↓
PostgreSQL
```

The AI layer never accesses PostgreSQL directly. All data is retrieved through the existing Spring Boot service layer, which is responsible for authentication, authorization, and persistence.

## 3. Components Implemented

### 3.1 Core Abstractions

| Component | Path | Purpose |
|-----------|------|---------|
| `AIRequest` | `com.neowallet.ai.dto.AIRequest` | User message with context |
| `AIResponse` | `com.neowallet.ai.dto.AIResponse` | Structured Neo response |
| `AIResponseType` | `com.neowallet.ai.dto.AIResponseType` | FACT, ANALYSIS, RECOMMENDATION, WARNING, INSUFFICIENT_DATA, REFUSAL |
| `Message` | `com.neowallet.ai.dto.Message` | Conversation message with role |
| `Conversation` | `com.neowallet.ai.dto.Conversation` | In-memory conversation foundation |
| `ToolExecutionRecord` | `com.neowallet.ai.dto.ToolExecutionRecord` | Tool audit record |
| `IntentType` | `com.neowallet.ai.dto.IntentType` | Classified user intent |

### 3.2 Agents / Services

| Component | Path | Responsibility |
|-----------|------|----------------|
| Neo Concierge | `NeoConciergeService` | Entry point, context, policy, audit |
| Intent Classifier | `IntentClassifier` | Deterministic keyword intent classification |
| AI Orchestrator | `AIOrchestrator` | Tool execution, prompt construction, provider call |
| Conversation Service | `ConversationService` | In-memory session store |

### 3.3 Policy Engine

| Permission | Allowed in MVP |
|------------|----------------|
| `READ_ONLY` | Yes |
| `RECOMMENDATION` | Yes |
| `FINANCIAL_EXECUTION` | No (explicitly denied) |

`PolicyEngine` is server-side and enforces the permission level before any tool is invoked. The policy decision is never based on the prompt alone.

### 3.4 Tool Registry

`ToolRegistry` holds the allowlist of approved tools. Six read-only tools were implemented:

- `getFinancialOverview`
- `getTransactions`
- `getBudget`
- `getSavingsGoals`
- `getBills`
- `getFinancialHealth`

All tools implement `NeowalletTool`, are Spring components, and have `isReadOnly() = true`.

### 3.5 AI Provider Abstraction

The existing `AIProvider` interface (`com.neowallet.provider.AIProvider`) is used. `StubAIProvider` is the active implementation for the foundation. The provider is configurable via `neowallet.ai.provider`.

### 3.6 Family Authorization

`AIController.resolveRole` uses `FamilyMemberRepository` to determine the user's role (`OWNER`, `MEMBER`, or `RESTRICTED`) for the requested family. Cross-family and non-member users resolve to `RESTRICTED`. No `ADMIN` role was introduced.

### 3.7 Audit

Every AI request is audited through the existing `AuditService` with:

- requester
- intent
- requested tools
- permission decision
- executed tools
- response type
- refusal status
- family context
- timestamp

Financial details are not stored in the audit log.

### 3.8 Prompt Injection Defenses

- `IntentClassifier` is deterministic; user input cannot override the classification.
- `PolicyEngine` is server-side and independent of the prompt.
- `ToolRegistry` is an explicit allowlist; unknown tools are ignored.
- `AIOrchestrator` constructs the LLM prompt from grounded tool results only.
- The provider prompt explicitly instructs the model not to invent numbers or perform actions.

## 7. Security & Financial Safety

- No payment execution code.
- No UPI, BBPS, bank transfer, P2P, wallet transfer, cash-out, add money, or withdraw logic.
- No stored-value or custodial funds.
- No direct SQL or database access from AI code.
- No ADMIN family role.
- AI cannot modify budgets, bills, savings goals, or transactions.
- All tools are read-only.
