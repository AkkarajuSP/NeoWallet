# NW-003.11.2 — Neo Concierge Conversational MVP Final Report

## Objective

Implement the first production-quality, read-only / recommendation-only Neo Concierge conversational experience on top of the existing Neo AI foundation.

## Scope

- Expand deterministic intent classification to support 9 financial intents plus follow-up and refusal categories.
- Enforce strict read-only and recommendation-only policies on the server side.
- Ensure all financial numbers come from authoritative read-only tools; the AI only explains and recommends.
- Add configurable cost-control parameters.
- Enrich AI audit records and response metadata.
- Defend against prompt injection and financial-action requests.
- Complete mobile chat UI states: conversation history, loading, error, retry, insufficient data, recommendation, and refusal.
- Add backend and Flutter tests.
- Run full regression and OpenAPI validation.
- Stop at NW-003.11.2; no work started on NW-003.11.3.

## Implementation Highlights

### Backend

- `IntentType.java` — added `FINANCIAL_OVERVIEW`, `TRANSACTION_ANALYSIS`, `BUDGET_ANALYSIS`, `SAVINGS_ANALYSIS`, `BILL_ANALYSIS`, `FINANCIAL_HEALTH_EXPLANATION`, `GENERAL_FINANCIAL_QUESTION`, `INSUFFICIENT_DATA`, and `UNSUPPORTED_REQUEST`.
- `IntentClassifier.java` — deterministic 9-intent classification with keyword checks and conversation-history inference for contextual follow-ups.
- `PolicyEngine.java` — updated `READ_ONLY_INTENTS` and `RECOMMENDATION_INTENTS` to include the new intents; denies all financial execution, money movement, write, and budget/savings modification intents.
- `AIOrchestrator.java` —
  - Builds prompts that separate authoritative tool data from conversation history.
  - Enforces `maxContextSize`, `maxResponseTokens`, `requestTimeoutMs`, `rateLimit`, and `conversationLimit`.
  - Returns typed responses: `FACT`, `ANALYSIS`, `RECOMMENDATION`, `WARNING`, `INSUFFICIENT_DATA`, and `REFUSAL`.
  - Handles provider failures and insufficient data safely.
- `AIContext.java` — added `maxResponseTokens` and `requestTimeoutMs` for provider-level grounding.
- `NeoConciergeService.java` — passes conversation history into intent classification and enriches audit metadata with intent, tools, authorization, response type, refusal, prompt/tool versions, and timestamp.
- `application.yml` — added `neowallet.ai` cost-control and version configuration.

### Mobile

- `ai_chat_screen.dart` —
  - Conversation history list.
  - User and AI message bubbles.
  - Loading indicator, error display, and retry button for the last user message.
  - Distinct visual treatment for refusal (orange), insufficient data (yellow), and recommendation (green) states.
- `ai_chat_provider.dart`, `ai_service.dart`, and `ai_message_model.dart` — retained and aligned with the backend response types.

### Safety

- No payment execution, UPI, BBPS, bank transfer, wallet transfer, P2P, cash-out, custodial fund, or autonomous financial action logic was introduced or enabled.
- No `ADMIN` family role was added or used.
- Refusal is server-side and does not depend on the AI provider.
