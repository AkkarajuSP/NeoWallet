# NW-003.12.0 — NeoWallet Mobile MVP Integration Assessment

## Scope

No application code was modified. This assessment reviews the current Flutter mobile application and backend integration to determine what is required to produce a cohesive production-quality NeoWallet MVP. NW-003.12.1 was not started.

- dio for HTTP

### Authentication issues
- `AuthInterceptor` clears secure storage on any `401` but does not emit a state change; the UI may still show the user as logged in until a rebuild occurs.
- No automatic token pre-refresh before expiry; `expiresIn` is stored but not used.
- `AuthInterceptor` only attaches the access token; it does not trigger refresh on `401`.

### Authorization issues
- `familyId` is passed via `state.extra` for some routes (`/finance/overview`, `/transactions`, etc.) and via `pathParameters` for others.
- Family ID is set in `X-Family-ID` header for most GET/POST calls, but missing for `transaction_service.update`, `transaction_service.delete`, `budget_service.update`, `budget_service.delete`, `savings_goal_service.update`, `savings_goal_service.delete`.

### Pagination issues
- All list services use `page` starting at 1, `limit` default 20. OpenAPI `Pagination` allows `page` and `limit` and has `totalCount` and `pageCount`; the Flutter models should be checked for `pageCount` handling.
- No "load more" UI is visibly present; pull-to-refresh is missing.

## 4. State management

### Architecture
- Riverpod `StateNotifier` pattern (deprecated in newer Riverpod versions).
- One provider per service for lists and one per screen for chat/financial health.
- `ref.watch` triggers on every state change.

### Findings

| Provider | Scope | Family-aware | Loading | Empty | Error | Issues |
|---|---|---|---|---|---|---|
| `authProvider` | global | no | yes | n/a | yes | No scheduled refresh, 401 handling not tied to UI |
| `profileProvider` | global | no | yes | n/a | yes | Single state for user + preferences |
| `familyProvider` | global | yes | yes | n/a | yes | Only one family; no switching cache |
| `financialOverviewProvider` | global | partially (param load) | yes | yes | yes | Not `.family`-scoped; does not auto-refresh on family switch |
| `transactionListProvider` | global | yes | yes | n/a | yes | Not `.family`-scoped; family switch leaks state |
| `budgetListProvider` | global | yes | yes | n/a | yes | Not `.family`-scoped; family switch leaks state |
| `savingsGoalListProvider` | global | yes | yes | n/a | yes | Not `.family`-scoped; family switch leaks state |
| `billListProvider` | global | yes | yes | n/a | yes | Not `.family`-scoped; family switch leaks state |
| `financialHealthProvider` | `.family` | yes | yes | n/a | yes | Family-scoped, but underlying service path prefix is broken |
| `aiChatProvider` | `.family` | yes | yes | n/a | yes | `sessionId` is always `null`; no conversation history |

### State issues
1. **Family-scoped providers missing.** Most list providers are global, so switching families will not reset the cache; stale data can be shown.
2. **Profile and auth are not family-aware.** Profile provider does not refresh when `familyId` changes.
3. **No central family switcher.** `familyProvider` holds one family; there is no provider for the active family context used by all feature providers.
4. **No refresh pattern.** Most screens load in `initState` only; pull-to-refresh and `onResume` refresh are not implemented.
5. **Excessive rebuilds.** `aiChatProvider(widget.familyId)` is watched at the screen level; every new message rebuilds the whole screen.

## 5. Navigation

### Current go_router setup
- `initialLocation`: `/splash` (or `/preview` in preview mode).
- Routes exist for splash, family, finance, bills, transactions, budget, savings, health, profile, AI.
- No redirect/guard logic.
- `errorBuilder` only shows text; no redirect to `/splash` or `/login`.

### Findings
1. **No protected routes.** Deep-linking to `/finance/overview` works even if unauthenticated (backend will reject, but UX is poor).
2. **No login/OTP/register routes.** The auth flow is not represented in `go_router`.
3. **No bottom navigation.** The MVP wants `HOME`, `FAMILY`, `NEO`, `PROFILE` tabs.
4. **Inconsistent family passing.** `familyId` is sometimes `extra`, sometimes `pathParameters`.
5. **No deep-link routing for family invitations.** `/family-invitations/{token}/accept` is not exposed as a mobile deep link.
6. **Back navigation.** Standard go_router back works, but there is no clear navigation hierarchy.
7. **Logout behavior.** `AuthNotifier.logout()` clears tokens but does not navigate to `/splash` or `/login`.
8. **Session expiry.** `401` errors delete tokens; no navigation is triggered from `AuthInterceptor`.

## 7. Financial UX

### Current distinction in `FinancialOverviewScreen`
The screen already separates:
- **Planning Values** — `planningIncome`, `mandatoryCommitments`, `essentialAllocation`, `savingsAllocation`, `emergencyAllocation`, `discretionaryPlanning`
- **Actual & Pending Records** — `actualTransactions`, `pendingPayments`, `committedAmount`
- **Available Financial Capacity** — `availableFinancialCapacity`

It also displays the `overview.disclaimer` in a `primaryContainer` card.

### Findings
- **Positive:** planning/actual/pending/capacity are visually grouped by section.
- **Risk:** numeric values are shown with 2 decimals and a currency suffix, but there is no visual label (icon, color, or helper text) explicitly telling the user that planning values are not bank balances. Relying only on the section title is likely insufficient for non-technical users.
- **Missing:** no tooltips or "i" info buttons explaining each value.
- **Missing:** no warning when `pendingPayments` exceed `availableFinancialCapacity`.
- **Missing:** `FinancialSummary` total income/expenses/savings and `budgetAdherence` are rendered in the same list, making it hard to distinguish authoritative planning numbers from summary aggregates.

## 8. Neo AI UX

### Current `AiChatScreen`
- One chat thread per `familyId`.
- User and Neo messages are shown in a `ListView`.
- `responseType` is rendered in uppercase as a small label.
- `refusal` → orange bubble; `INSUFFICIENT_DATA` → yellow; `RECOMMENDATION` → green; others → grey.
- `LinearProgressIndicator` while loading.
- Error message with a retry button that resends the last user message.

### Findings
- **Positive:** refusal/insufficient/recommendation are visually differentiated.
- **Positive:** `responseType` label helps distinguish facts from recommendations.
- **Missing:** conversation history (no sessions). `sessionId` is always `null` and the `POST /ai/chat` endpoint is used in a stateless manner.
- **Missing:** conversation list (`/ai/conversations` not used).
- **Missing:** follow-up suggestion chips.
- **Missing:** scroll-to-bottom when new message arrives.
- **Risk:** error retry resends the exact same last user message, but if the error was a persistent 5xx or 401 it will loop.
- **Performance:** `ref.watch(aiChatProvider(widget.familyId))` rebuilds the entire scaffold and message list on every character state change? No, only after `state` updates. Still, full scaffold rebuild on each message.

## 9. Security

### Token storage
- `FlutterSecureStorage` with `encryptedSharedPreferences: true` on Android.
- iOS defaults to keychain.
- Tokens are deleted on logout and on `401`.

### Findings
- **Missing automatic token refresh.** `AuthService.refresh()` exists but is not called proactively; `AuthNotifier.refresh()` exists but is not scheduled.
- **Logout does not navigate.** Tokens are cleared but the UI may remain on a protected screen.
- **401 handling does not propagate.** `AuthInterceptor` deletes tokens but does not notify `AuthProvider`; no redirect.
- **No certificate pinning.** Trusting all server certificates on an unconfigured dio instance.
- **Public path list is hard-coded.** Maintainable, but could include `health` check if used.
- **No request/response body redaction.** `AuthInterceptor` avoids logging headers but does not prevent body logging elsewhere.
- **No screenshot/screen recording protection.** The app does not set `FLAG_SECURE` or iOS `isCaptured` restrictions.
- **Family isolation is header-based.** `X-Family-ID` is sent for most reads, but several PUT/DELETE calls omit it, which may allow cross-family writes if the backend relies on the header.
- **DioException messages may expose paths/bodies to the UI.** Error mapping in providers uses `e.toString()` or `e.message` directly.

## 11. Performance

### Potential issues
1. **No lazy image handling.** No cached images or skeleton loaders.
2. **Full-screen rebuilds.** `AiChatScreen` and `FinancialOverviewScreen` watch the whole provider and rebuild the full `Scaffold`.
3. **List loading on `initState` only.** No `RefreshIndicator` or infinite scroll; returning to a screen does not refresh.
4. **No request deduplication.** Two consecutive `ref.watch` in different widgets can trigger parallel identical requests.
5. **No response caching.** Riverpod state is in-memory only; no offline support.
6. **Large financial model re-serialization.** `fromJson` is synchronous and called on every response.
7. **AI chat serialization on every message.** `AiMessageModel.fromJson` with `DateTime.tryParse` and fallback keys.
8. **No debounce on family switching.** A fast switch could trigger multiple in-flight requests.
9. **Startup.** No splash pre-fetch; splash just shows text and waits for navigation.

## 14. Recommended implementation sequence

1. **Auth flow:** Create `LoginScreen`, `RegisterScreen`, `OtpScreen`; add routes; wire auth state to `go_router` redirect.
2. **Router guards:** Add `redirect` logic in `go_router` to send unauthenticated users to `/login` and authenticated users to `/home`.
3. **Home + bottom nav:** Implement `HomeScreen` with `HOME`, `FAMILY`, `NEO`, `PROFILE` bottom tabs and a dashboard grid for `FinancialOverview`, `Transactions`, `Budget`, `Savings`, `Bills`, `FinancialHealth`.
4. **Fix `FinancialHealthService` API path:** Add `/api/v1` prefix to all `financial-health` calls.
5. **Family-scoped providers:** Convert `transactionListProvider`, `budgetListProvider`, `savingsGoalListProvider`, `billListProvider`, `financialOverviewProvider` to `.family` keyed by `familyId`; create an `activeFamilyProvider`.
6. **Token refresh + 401 handling:** Schedule pre-emptive refresh and emit `AuthProvider` logout on 401, then navigate to `/login`.
7. **Security hardening:** Add `FLAG_SECURE`/iOS screen capture block, redact dio logs, ensure `X-Family-ID` on all mutating endpoints.
8. **Neo AI conversation history:** Add session support, conversation list, and follow-up chips.
9. **UX polish:** Create shared `EmptyStateWidget`, `ErrorStateWidget`, `LoadingStateWidget`, pull-to-refresh, info tooltips for planning values.
10. **Test suite:** Add widget/unit tests for auth, profile, family, financial overview, budget, savings, bills, AI.
