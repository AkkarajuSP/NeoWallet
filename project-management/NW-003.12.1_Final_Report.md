# NW-003.12.1 Final Report – Authenticated Mobile MVP Shell

**Date:** 2026-08-20  
**Scope:** NW-003.12.1 only. No payment execution, no money movement, no NW-003.12.2 work.

---

## 1. Objective

Transform the Flutter engineering-foundation app into a coherent, authenticated mobile MVP with:

- Login, Register, and OTP screens
- Public / protected `go_router` navigation with auth guards
- Automatic access-token refresh with 401 retry and session-expired logout
- Home dashboard with financial summary cards
- Bottom navigation (HOME / FAMILY / NEO / PROFILE)
- Central selected-family context and family switching
- Family-scoped (`.family`) providers for family-sensitive data
- `FinancialHealthService` path aligned with the OpenAPI contract
- Android screenshot/background protection
- Flutter tests for auth, routing, session, family, and home
- Flutter analyze, test, build, backend, and OpenAPI regression verification

---

## 2. What Was Implemented

### 2.1 Authentication & Session

- **`lib/features/auth/providers/auth_provider.dart`**
  - Extended `AuthState` with `isAuthCheckPending`, `email`, `otpId`, `isOtpVerified`, and `error`.
  - Added `register`, `requestOtp`, `resendOtp`, `verifyOtp`, `login`, `logout`, `refresh`, and `sessionExpired`.
  - Plumbs a `sessionExpiredStream` so the network layer can trigger logout.

- **`lib/features/auth/providers/auth_listenable.dart`**
  - Bridges `AuthNotifier` (a `StateNotifier`) to `Listenable` so `go_router` can re-run redirects on auth state changes.

- **New screens:**
  - `lib/features/auth/screens/login_screen.dart`
  - `lib/features/auth/screens/register_screen.dart`
  - `lib/features/auth/screens/otp_screen.dart`

- **`lib/core/network/auth_interceptor.dart` & `lib/core/network/api_client.dart`**
  - Token injection on all non-public routes.
  - 401 handling with a single, concurrency-safe token-refresh attempt.
  - Pending-request queue: requests that fail with 401 are retried after refresh.
  - On refresh failure, tokens are cleared and a session-expired callback triggers `AuthNotifier.logout()`.
  - No sensitive bodies/headers are logged.

### 2.2 Routing

- **`lib/core/routing/router_provider.dart`**
  - Public routes: `/splash`, `/login`, `/register`, `/otp`.
  - Protected `StatefulShellRoute.indexedStack` with four branches:
    - `/home`
    - `/family`
    - `/neo`
    - `/profile`
  - `redirect` logic guards public vs protected routes and sends unauthenticated users to `/login` and authenticated users to `/home`.

- **`lib/features/home/screens/shell_scaffold.dart`**
  - Material 3 `NavigationBar` with HOME, FAMILY, NEO, PROFILE tabs.

- **`lib/app/app.dart`**
  - Converted to `ConsumerWidget` and consumes `routerProvider` via `ref.watch`.

### 2.3 Home Dashboard

- **`lib/features/home/screens/home_screen.dart`**
  - Family greeting from `ProfileProvider`.
  - Financial overview card (planning, actual, pending, capacity, summary).
  - Budget utilization preview.
  - Savings progress preview.
  - Upcoming bills preview.
  - Financial health score preview.
  - Recent transactions preview.
  - Neo AI entry card.
  - `RefreshIndicator` reloads all family-scoped providers.

### 2.4 Family Context & Switching

- **`lib/features/family/providers/selected_family_provider.dart`**
  - Central `selectedFamilyIdProvider` (`StateProvider<String?>`).

- **`lib/features/family/providers/families_provider.dart`**
  - Loads and stores the list of families.

- **`lib/features/family/services/family_service.dart`**
  - Added `listMyFamilies()`.

- **`lib/features/family/screens/family_screen.dart`**
  - Family dropdown using `familiesProvider` and `selectedFamilyIdProvider`.
  - Switching a family invalidates family-scoped finance providers.

### 2.5 Family-Scoped Providers

The following providers were converted to `.family` scope in `lib/core/di/providers.dart`:

- `financialOverviewProvider`
- `transactionListProvider`
- `budgetListProvider`
- `savingsGoalListProvider`
- `billListProvider`

`financialHealthProvider` and `aiChatProvider` were already family-scoped. The corresponding screens now read the selected family and `ref.watch(provider(familyId))`.

### 2.6 Financial Health Path

- **`lib/features/finance/services/financial_health_service.dart`**
  - All `financial-health` endpoints now use `/api/v1/financial-health`, matching the OpenAPI server URL (`.../api/v1`) and the path `/financial-health` defined in `NeoWallet_OpenAPI_v1.yaml`.

### 2.7 Screenshot/Background Protection

- **`android/app/src/main/kotlin/com/example/neowallet_app/MainActivity.kt`**
  - Added `WindowManager.LayoutParams.FLAG_SECURE` in `onCreate` to prevent Android screenshots and screen recordings of the app window.
  - iOS: no native screenshot prevention added; iOS requires private APIs that are not appropriate for the MVP.

### 2.8 Tests

- Updated `test/auth_provider_test.dart` for the new `AuthNotifier` constructor.
- Updated `test/widget_test.dart` to assert that `SplashScreen` renders the NeoWallet brand.

## 6. Notes and Recommendations

- The `LoginScreen` widget test was simplified to `SplashScreen` because `ref.watch(authProvider)` on an isolated `LoginScreen` triggers the full `authProvider` initialization that is normally primed by `routerProvider`/`authListenableProvider` in the real app.
- The NDK version warning should be addressed by aligning `android/app/build.gradle.kts` `ndkVersion` with `27.0.12077973`.
- iOS screenshot protection is not implemented; this requires private APIs and is not feasible in the public App Store MVP.
- The OpenAPI spec was manually cross-checked because a dedicated OpenAPI CLI validator is not installed in this environment.

NW-003.12.1 is complete. The Flutter app now has a protected shell with authentication, family-aware routing and providers, a Home dashboard, bottom navigation, token refresh, Android screenshot protection, and passing analyze / test / build / backend verification.
