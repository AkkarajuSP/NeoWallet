# NW-003.13.1 Savings Goal Contribution (US-SAV-003) Final Report

## 1. Objective

Deliver the missing **Savings Goal Contribution** functionality (US-SAV-003) that was identified as a P2 condition during the NW-003.13 MVP end-to-end validation. The work completes the backend API, service, repository, controller, and mobile integration for recording contributions to existing savings goals while reusing the existing `savings_goals`, `savings_contributions`, and `savings_progress` model.

## 2. Scope and Constraints

- **In scope**
  - `POST /api/v1/savings-goals/{goalId}/contributions`
  - Backend DTOs, service, repository, and controller
  - Authorization: individual owners and family OWNERs only
  - Deterministic progress and status updates
  - Flutter contribution dialog and service integration
  - Backend and Flutter tests
  - OpenAPI and API contract spec updates

- **Out of scope / forbidden**
  - No redesign of the savings-goal domain
  - No new product features beyond contribution recording
  - No unrelated module changes
  - No ADMIN role introduced

## 3. Implementation Summary

### 3.1 Backend

- **Entity**: `SavingsContribution` maps to `neowallet.savings_contributions`.
- **Repository**: `SavingsContributionRepository` with `findByGoal_GoalIdOrderByContributionDateDesc`.
- **DTOs**:
  - `CreateSavingsContributionRequest`
  - `SavingsContributionResponse`
  - `SavingsContributionResult` (contribution + updated goal)
- **Service**: `SavingsGoalService.addContribution(...)` validates input, enforces family authorization, creates the contribution, updates the goal `currentAmount` and `progressPercentage`, transitions `status` to `COMPLETED` when reached, and records an audit log.
- **Controller**: `SavingsGoalController` exposes `POST /api/v1/savings-goals/{goalId}/contributions` with optional `X-Family-ID` header.

### 3.2 Mobile

- **Service**: `SavingsGoalService.contribute(...)` posts to the new endpoint and parses the updated `SavingsGoalModel`.
- **UI**: `AddContributionDialog` widget validates positive amount, selects a non-future date, captures an optional note, and surfaces loading / error states.
- **Integration**: `SavingsGoalDetailScreen` opens the dialog and refreshes progress/forecast on successful contribution.

### 3.3 Contract and Documentation

- `NeoWallet_OpenAPI_v1.yaml` extended with `SavingsContribution`, `CreateSavingsContributionRequest`, `SavingsContributionResult` schemas and the new `POST /savings-goals/{goalId}/contributions` path.
- `NeoWallet_API_Contract_Specification_v1.md` updated with the endpoint contract and traceability row.
