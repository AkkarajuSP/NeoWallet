# NW-003.13.6 Splash Screen Routing Fix — Final Report

**Date:** 26 Aug 2026  
**Task:** Fix the NeoWallet Flutter splash screen hang on physical Android devices by correcting `GoRouter` redirect logic.  
**Constraint:** Modify ONLY splash routing behavior in `lib/core/routing/router_provider.dart` and add automated tests. No changes to authentication logic, `SecureStorage`, API configuration, backend, database, business logic, or splash screen UI. Do not start UAT or NW-003.15.

## Root Cause

`lib/core/routing/router_provider.dart` redirected every non-public route to `/splash` while `isAuthCheckPending` was `true`, but never redirected `/splash` away once the auth check completed. On a physical device the `AuthNotifier` finished `_loadFromStorage()` but the UI stayed on `SplashScreen`, because the router had no rule to leave `/splash`.

## Fix Applied

File: `lib/core/routing/router_provider.dart`

Added a `/splash` specific redirect branch in the `GoRouter` `redirect` callback:

```dart
if (location == '/splash') {
  if (auth.isAuthCheckPending) return null;
  return auth.isAuthenticated ? '/home' : '/login';
}
```

- Pending auth check: remain on `/splash`.
- Completed + unauthenticated: redirect to `/login`.
- Completed + authenticated: redirect to `/home`.

No other application, authentication, storage, API, backend, or feature logic was modified.

## Automated Tests Added

File: `test/routing/router_provider_test.dart`

Three widget tests were added:

1. **Pending auth:** user remains on `SplashScreen` while `isAuthCheckPending` is `true`.
2. **Unauthenticated:** user is routed from `/splash` to `LoginScreen`.
3. **Authenticated:** user is routed from `/splash` to `HomeScreen`.

Fakes were used for `AuthNotifier`, `SecureStorage`, `ApiClient`, `ProfileNotifier`, and `FamiliesNotifier` to keep tests isolated and free of network or secure-storage side effects.
