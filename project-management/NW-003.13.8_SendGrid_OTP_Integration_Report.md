# NW-003.13.8 — SendGrid OTP Provider Integration Report

**Date:** 2026-08-27  
**Scope:** Implement SendGrid as the real OTP email provider for NeoWallet UAT.

---

## 1. Provider Configuration Status

The OTP provider is controlled by the existing `neowallet.otp.provider` property:

```
neowallet.otp.provider=${NEOWALLET_OTP_PROVIDER:stub}
```

For SendGrid, set:

```
NEOWALLET_OTP_PROVIDER=sendgrid
SENDGRID_API_KEY=<read from backend environment at runtime>
SENDGRID_FROM_EMAIL=<verified SendGrid sender email>
```

No secrets are hard-coded in the source, `application.yml`, `application-dev.yml`, or mobile configuration. `StubOtpProvider` remains the default for local development.

## 2. Implementation Files

### 2.1 New provider

- **File:** `neowallet/backend/neowallet-api/src/main/java/com/neowallet/provider/sendgrid/SendGridOtpProvider.java`
- **What it does:**
  - Implements the existing `OtpProvider` interface.
  - Activates only when `neowallet.otp.provider=sendgrid` (`@ConditionalOnProperty`).
  - Reads `SENDGRID_API_KEY` and `SENDGRID_FROM_EMAIL` via `@Value` at runtime.
  - Constructs a `com.sendgrid.SendGrid` client and sends the OTP via `POST /mail/send`.
  - Sends the email subject/body using the provided `purpose` and `plainOtp`.
  - Throws `IllegalStateException` on non-2xx SendGrid responses or I/O errors.
  - Does **not** log plaintext OTP values or the API key.
  - Keeps `StubOtpProvider` intact and leaves all other OTP logic (generation, hashing, expiry, replay, rate limiting, account lockout, JWT/session) unchanged.

### 2.2 Dependency

- **File:** `neowallet/backend/neowallet-api/pom.xml`
- **Change:** Added the official SendGrid Java SDK:

```xml
<dependency>
    <groupId>com.sendgrid</groupId>
    <artifactId>sendgrid-java</artifactId>
    <version>4.10.1</version>
</dependency>
```

### 2.3 Unchanged files

- `OtpProvider.java`

## 5. Email Submission Result

A live real-email UAT smoke test was **not performed**.

**Blocker:** The UAT runtime environment does not contain:

1. `SENDGRID_FROM_EMAIL` (verified SendGrid sender address)
2. A Product Owner test email address

`NEOWALLET_OTP_PROVIDER` is also not currently set to `sendgrid` in the process/user/machine environment.

The implementation is ready for the live smoke test as soon as these three values are provided and the backend JAR is launched with them.

When enabled, the expected flow is:

1. Registration → `AuthService.register()` → `OtpService.requestOtp()`.
2. `OtpService` generates, hashes, persists, and then calls `OtpProvider.sendEmail(...)`.
3. `SendGridOtpProvider` calls `POST https://api.sendgrid.com/v3/mail/send`.
4. On 2xx HTTP status, the OTP is submitted to SendGrid for delivery.
5. `OtpService.verifyOtp(...)` continues to enforce max attempts, expiry, and replay protection unchanged.
