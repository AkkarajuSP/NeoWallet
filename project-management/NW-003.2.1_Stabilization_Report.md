## 1. Flyway Migration Discipline

- `V2__identity.sql` was already applied to `neowallet_test` as `TEXT`. To adhere to forward-only migration discipline, **V2 was not modified**. A new migration `V3__audit_metadata_jsonb.sql` was created.
- `V3` conditionally converts `audit_logs.metadata` from `TEXT` to `JSONB` only when the column is still `TEXT`, and clears empty `metadata` values before casting.
- `mvn org.flywaydb:flyway-maven-plugin:9.22.3:validate` passes against both `neowallet_test` and `neowallet_dev`.
- Final migration history (`neowallet_test`):
  - `1 baseline`
  - `2 identity`
  - `3 audit metadata jsonb`

## 2. Audit Metadata JSONB + JPA

- Added `io.hypersistence:hypersistence-utils-hibernate-63:3.15.4`.
- `AuditLog.metadata` now maps to `com.fasterxml.jackson.databind.JsonNode` with `@Type(JsonBinaryType.class)`.
- `AuditService` parses the incoming JSON string with `ObjectMapper`, storing `null` for blank/invalid input.
- Confirmed in `neowallet_test`:
  - `information_schema.columns` reports `metadata` as `jsonb`.

## 8. OpenAPI Validation

Implemented auth endpoints match the base path (`/api/v1`) and paths in `NeoWallet_OpenAPI_v1.yaml`. Two mismatches found:

- `POST /auth/logout` implementation requires a `RefreshTokenRequest` request body. The OpenAPI spec defines `requestBody: none` for this operation.
- `POST /auth/logout-all` is implemented but not defined in the OpenAPI spec.

**Severity: MEDIUM** — runtime works, but the contract is incomplete. These should be fixed in the spec before any consumer integration.
