## 4. Database Migrations

**`V4__user_profile_preferences.sql`** created:

- `neowallet.families` — required as the FK target for `user_profiles.family_id`
- `neowallet.user_profiles` — profile fields and `family_role`
- `neowallet.user_preferences` — notification, frequency, and AI preferences
- Seeded default rows for existing `users`

The migration was validated by Flyway (5 migrations total, schema version 4).

## 5. API Endpoints Implemented

All endpoints derive the user identity from the JWT (`@AuthenticationPrincipal UserDetails`); no client-supplied user ID is trusted.

| Method | Path | OpenAPI `operationId` | Purpose |
|---|---|---|---|
| GET | `/api/v1/users/me` | `getCurrentUser` | View own profile |
| PUT | `/api/v1/users/me` | `updateCurrentUser` | Update own profile |
| DELETE | `/api/v1/users/me` | `deleteCurrentUser` | Soft-delete own account |
| GET | `/api/v1/users/me/preferences` | `getUserPreferences` | View preferences |
| PUT | `/api/v1/users/me/preferences` | `updateUserPreferences` | Update preferences |

## 8. Security Tests

| Test | Result |
|---|---|
| User A cannot read User B profile | **PASS** — `GET /users/me` returns only the token owner's data; test asserts response body contains the token subject's `userId` only |
| User A cannot modify User B profile | **PASS** — `PUT /users/me` derives `userId` from JWT |
| Manipulated user ID cannot bypass authorization | **PASS** — endpoints are `/me`; no `userId` path variable is accepted |
| Expired JWT cannot access profile | **Not automated** — current access-token TTL is 15 minutes; the `JwtAuthenticationFilter` rejects expired tokens. Automated test requires waiting or a separate token generator; not modified per instruction to not alter authentication architecture |
| Revoked session cannot access profile | **Not automated** — `JwtAuthenticationFilter` validates the token itself, not the session state. Revocation applies to refresh tokens. Per instruction, authentication architecture was not modified |

## 10. Architecture Deviations / Known Issues

1. **`families` table creation**: `V4` includes a minimal `families` table because the approved `user_profiles.family_id` FK references `families(family_id)`. The `family_members` table and family-management business logic are **not** implemented.
2. **Account deletion guard**: `DELETE /users/me` rejects family owners but cannot check "active financial commitments" because budget, bills, transactions, and savings tables are out of scope.
3. **Preferences completeness vs. contract**: `user_preferences` stores additional fields (`budget_alert_threshold_percentage`, `savings_updates_frequency`, `financial_health_updates_frequency`) per the data dictionary, but the `UserPreferences` OpenAPI schema does not expose them. Those columns remain at their defaults.
4. **Expired / revoked session tests**: Cannot be fully automated without modifying the approved `JwtAuthenticationFilter`. This is a security-test gap noted above.

## 11. Technical Debt
