# NW-003.8 Savings Goals Implementation — Final Report

## 1. Objective

Implement the **Savings Goals** capability for the NeoWallet MVP, covering:

- Database schema (Flyway V9)
- Backend domain (entity, repository, DTOs, service, controller)
- Deterministic progress and forecast calculations
- Family authorization and security tests
- Flutter mobile screens (list, create, detail)
- Regression, Flyway, OpenAPI, and Flutter build verification

## 2. Implementation Summary

### 2.1 Database — Flyway V9

File: `neowallet/backend/neowallet-api/src/main/resources/db/migration/V9__savings_goals.sql`

Created:
- `savings_goals` — stores goal metadata, target amount, current amount, currency, priority, category, status
- `savings_contributions` — tracks contribution history
- `savings_progress` — stores snapshot progress records

Includes constraints, indexes, and `NUMERIC(15,2)` monetary fields. Soft delete is implemented via status `CANCELLED`.

### 2.2 Backend Domain

Files:
- `SavingsGoal.java` — JPA entity
- `SavingsGoalRepository.java` — Spring Data JPA repository
- `CreateSavingsGoalRequest.java`, `UpdateSavingsGoalRequest.java`
- `SavingsGoalResponse.java`, `SavingsGoalListResponse.java`
- `SavingsGoalProgressResponse.java`, `SavingsGoalForecastResponse.java`
- `SavingsGoalService.java` — business logic, progress/forecast calculations, family authorization
- `SavingsGoalController.java` — REST endpoints
- `SavingsGoalControllerTest.java` — integration tests
- `FinancialOverviewRepository.java` — extended query for affordability checks

Endpoints implemented:
- `POST /api/v1/savings-goals`
- `GET /api/v1/savings-goals`
- `GET /api/v1/savings-goals/{goalId}`
- `PUT /api/v1/savings-goals/{goalId}`
- `DELETE /api/v1/savings-goals/{goalId}`
- `GET /api/v1/savings-goals/{goalId}/progress`
- `GET /api/v1/savings-goals/{goalId}/forecast`

Authorization:
- `RESTRICTED` family members are blocked from creating goals.
- Updates/deletes restricted to family `OWNER`.
- Any family member may view goals in their family.

## 4. Findings

- **Monetary precision**: all backend money fields use `BigDecimal` with `NUMERIC(15,2)`.
- **Deterministic calculations**: progress percentage, remaining amount, required monthly contribution, on-track status, and forecast scenarios are computed in `SavingsGoalService`.
- **No money movement**: implementation is purely planning/tracking; no payment or bank integration.
- **Family authorization**: enforced in service layer using `FamilyMemberRepository` roles.
- **Soft delete**: `CANCELLED` status used instead of a `deleted_at` column.
- **OpenAPI alignment**: endpoint paths, request/response schemas, and enums match the approved `NeoWallet_OpenAPI_v1.yaml`.
- **Test coverage**: `SavingsGoalControllerTest` covers CRUD, progress, forecast, and role-based authorization.
