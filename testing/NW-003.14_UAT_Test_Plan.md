# NW-003.14 — NeoWallet MVP UAT Test Plan

## 1. Overview

**Objective:** Prepare and execute structured User Acceptance Testing (UAT) for the NeoWallet MVP before release.

**Scope:** All 72 MVP user stories across 11 features. No new features will be introduced unless a P0/P1 defect requires it.

**Status:** NW-003.13 and NW-003.13.1 are approved. The missing `US-SAV-003` Savings Goal contribution endpoint is now implemented.

---

## 2. UAT Environment

| Component | Requirement | Verification Method |
|---|---|---|
| Backend API | `neowallet-api` running on UAT host | `mvn clean verify` / health endpoint |
| PostgreSQL | Latest schema with Flyway migrations | `SELECT 1` and migration checksum query |
| Redis | Available for session/refresh tokens | `redis-cli ping` or startup log |
| AI Service | Neo AI provider configured | Test `/api/v1/neo/chat` health |
| Flutter APK | Debug or release APK built | `flutter build apk` |
| Environment Config | `.env` or application properties point to UAT | Inspect API base URL and keys (no secrets shown) |
| Auth Provider | JWT issuer, access/refresh token config | Login/refresh token cycle |
| OTP Provider | OTP generation/validation active | Register + OTP verify |
| Email / SMS / Push | Configured but not UAT-blocking | Verify notification schema |

**Note:** Production secrets will not be exposed in any UAT artifact.

| # | User Journey | Target User Stories |
|---|---|---|

### 3.2 Out of Scope

- Payments, UPI, BBPS, P2P, bank transfers, cash-out, stored-value wallet, custodial funds.
- ADMIN family role.
- Payment architecture or PolicyEngine changes.
- Non-MVP features not listed in the 72 user stories.

## 4. UAT Entry Criteria

- [x] All backend tests pass (`mvn clean verify`).
- [x] All Flutter tests pass (`flutter test`).
- [x] Flutter `apk --debug` builds successfully.
- [x] OpenAPI contract validates (`npx swagger-cli validate`).
- [x] `US-SAV-003` contribution endpoint implemented and tested.
- [x] UAT environment (API, DB, Redis, AI) is provisioned.
- [x] UAT Test Cases reviewed and approved by Product Owner.
- [ ] Real Android device available for mobile-device test (to be confirmed during UAT).

---

## 5. UAT Exit Criteria

- All P0 and P1 defects are resolved or formally accepted.
- All critical user journeys (A–P) pass.
- Authentication, family isolation, financial safety, Neo AI safety, and savings contribution pass.
- Real-device smoke test passes.
- UAT Defect Register and Execution Report are signed off.

## 8. Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| No real Android device available | P2 | Use at least one Android emulator; document device coverage gap |
| AI provider rate limits | P3 | Use dedicated UAT API key; cache non-sensitive responses |
| OTP delivery delays | P3 | Configure test OTP bypass or use test inboxes |
| Backend not reachable from device | P1 | Use shared UAT network and HTTPS/TLS config |
